# Отчёт о проверках «Рабочей недели»

**Итог — требует проверки на устройстве.** Проверки на физическом телефоне по согласованию с пользователем исключены из этого прогона. В таблице PASS относится к указанной среде. Для смешанных сценариев перечислены выполненные части и открытые условия.

Из 46 сценариев разделов 14–16 статус PASS получили 33. Ещё 13 имеют статус BLOCKED из-за отсутствия работающего Android-устройства. Число сценариев PRD отличается от числа автоматических тестов, поскольку один сценарий может охватывать несколько проверок.

## Среда и доказательства

- Windows 10 x64, Ryzen 5 5600H, JDK Temurin 17.0.21.1+2, Gradle Wrapper 9.3.1, AGP 9.1.1, SDK 37.0. Первая сборка создала Room-схему версии 1 и APK для API 26–37.
- Автоматизация использует JUnit 4, Robolectric 4.16.1, нативный SQLite и графический рендеринг Android. Тестовые экраны открывают основную Activity и взаимодействуют с реальными Compose-компонентами. Изображения сняты с окна Activity. Системная шторка, клавиатура производителя и значки системных панелей в этот рендер не входят.
- Штатный Android Emulator на Windows сообщил об отсутствии драйвера аппаратного ускорения. Попытки запустить API 26 и 37 с программной эмуляцией не дали загрузившегося устройства в ADB. Системные драйверы Windows не изменялись. Для instrumented tests отдельно собран тестовый APK, отдельный запуск `connectedDebugAndroidTest` записан в журнал.
- При первом запуске JVM-тестов загрузчик Java 17 не нашёл классы по пути с кириллицей. Контрольный эксперимент с одним и тем же JUnit-классом воспроизвёл ошибку в UTF-8 аргументном файле Windows и дал 7/7 в кодировке системного пути. Повторная сборка использовала NTFS junction к тем же исходникам. Команды приведены в README.
- Первичная приёмка выявила неоднозначный селектор свайпа и ненадёжную проверку двойного нажатия. Окончательные тесты адресуют тело карточки и дважды вызывают действие именно текущей кнопки сохранения до следующей отрисовки.
- По отдельному запуску `CalendarRulesTest` прошли 7/7. Результат не суммируется с полным прогоном Gradle.

## Как закрыть проверки на устройстве

1. На выделенной установке выполнить `gradlew.bat -PisolatedTest :app:connectedDebugAndroidTest`. Для UI smoke использовать API 26 и 37. На API 33 и 34+ отдельно пройти системный запрос разрешения, запрет канала и возврат из настроек. На API 35+ пройти force-stop и повторное открытие.
2. На телефоне сохранить контрольную запись и оформить сводку на завтра. Для REM-12 назначить T минимум за 65 минут до полуночи. Отключить Doze и Battery Saver для контрольного прогона по PRD, разрешить канал, оставить приложение в фоне. Сравнить строки `Scheduled`, `Callback received`, `Published digest` в `adb logcat -s PlannerReminder` и саму карточку в шторке. В отдельном прогоне включить энергосбережение и записать фактическую задержку.
3. Зафиксировать ID, дату, текст и настройки, перезапустить Android, разблокировать и установить APK с той же подписью поверх через `adb install -r`. Проверить данные, календарь, выдачу, расписание и переход по ранее опубликованному уведомлению.
4. Для PERF-01 использовать одну зафиксированную модель телефона и release/profileable без отладчика. Загрузить 10 000 детерминированных записей, 100 дел в одном дне. Записать 20 холодных запусков, по 30 переходов, сохранений и запросов. p95 — элемент с номером ceil(0,95 × N) отсортированного ряда. Бюджеты составляют 2000, 200, 300 и 500 мс соответственно.
